# Code and edits

- Match the **existing style** of the file you're editing. The project has a formatter — let it
  decide formatting.
- Make the **smallest change** that solves the task. Do not reformat or refactor unrelated code.
- When explaining an edit, show only the relevant region, not the whole file.
- Add or update tests when you change behavior.
- Prefer existing utilities and patterns in the codebase over introducing new dependencies.
