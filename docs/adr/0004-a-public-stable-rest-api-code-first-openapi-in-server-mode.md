# 0004. A public, stable REST API, code-first OpenAPI via utoipa, in Server mode only

- Status: Proposed
- Date: 2026-11-11

Decided in [API contract and codegen pipeline](https://github.com/dyle71/flock/issues/13).

## Context

flock's SPA talks to the Rust backend only over HTTP, in the desktop app as well as in a browser
([0003](0003-one-binary-two-runtime-modes.md)). klicker.ing, the model project, describes its
REST API with a code-first OpenAPI document, generated, committed and guarded against
staleness, and consumes it through openapi-typescript and openapi-fetch (klicker.ing ADR 0011).
klicker.ing kept that API internal at first and published a small, stable subset later
(klicker.ing ADR 0017).

The research on OpenAPI tooling (`docs/research/openapi-codegen-and-push.md`) found that on axum
only utoipa and aide produce OpenAPI 3.1; utoipa has the larger user base and an opt-in path to
OpenAPI 3.2, while aide's next major has been in alpha for months. Spec-first has no mature axum
server generator. openapi-typescript reads 3.1 but not yet 3.2, whose `itemSchema` is the only
standard way to type an SSE stream. [0003](0003-one-binary-two-runtime-modes.md) already fixed
Server-Sent Events as the push channel.

The maintainer weighed an internal API for the SPA alone against a public one on 2026-11-11 and
chose the public, stable interface, so that scripts and other applications can work with flock.

## Decision

- **Code-first OpenAPI 3.1, generated by utoipa** from the axum handlers. A Rust test or `xtask`
  writes `docs/api/openapi.json` and the TypeScript types; both are committed, and a guard fails
  when either is stale. `GET /api/v1/openapi.json` serves the document at runtime. The SPA uses
  openapi-typescript, openapi-fetch and openapi-react-query, and nothing else, to call the API.
- **Conventions follow klicker.ing ADR 0011**: domain paths under `/api/v1/`, RFC 9457
  `problem+json` errors with a stable `code`, the same-origin check for cookie requests with
  unsafe methods. Message lists page by cursor; small collections by `offset` and `limit`.
- **One SSE stream** per session, `/api/v1/events`, of invalidation hints with small payloads,
  monotonic ids, resume by `Last-Event-ID` and a `resync` event. Its payloads are
  `components.schemas` of the same document; the stream itself is described as
  `text/event-stream` until the tooling reads OpenAPI 3.2.
- **The domain API is public and stable, in Server mode only.** Local mode stays reachable by the
  desktop app alone. Scripts and applications authenticate with **Access tokens** a User creates,
  carrying the Scopes `read`, `write` and `send`; Bearer requests are exempt from the same-origin
  check and rate-limited per token.
- **The stability promise** covers everything under `/api/v1/`, events included, and starts
  with flock 1.0.0; until then the document is marked `info.x-stability: unstable`. Within v1
  changes are additive only and clients ignore unknown fields and enum values; a breaking change
  goes to `/api/v2/`, deprecated operations carry `Deprecation` and `Sunset` headers, and v1 is
  served for at least 12 months after v2 appears. Admin endpoints and the sign-in flows under
  `/api/auth/*` are not covered.
- **Documentation** is the OpenAPI document plus a guide in `docs/api/` with tested examples;
  the binary serves no reference UI.

## Consequences

- The SPA and every third party use the same API; there is no internal layer the promise does not
  bind, so every endpoint the SPA needs is designed as a public one.
- From 1.0.0 on, renaming a field, tightening a parameter or changing an event's meaning requires
  a new API version and a year of serving both.
- The guard keeps document, TypeScript types and handlers in step; a change to a handler without
  regenerating fails the tests.
- Access tokens add a second way to authenticate and a store of hashed secrets in Server mode.
- Moving to OpenAPI 3.2 and typing the SSE stream waits on openapi-typescript; an OAuth2
  authorization server, a reference UI and a public API in Local mode are not part of v1.
- The terms are fixed in `CONTEXT.md` (**Access token**, **Scope**).
